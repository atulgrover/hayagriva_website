Each case carries a case_manifest.json that stores: ingest_mode (interactive / batch), file domain classifications, scheduled CIRP milestone wake events, active RAG document selections, and the session state snapshot used for context compaction.

Context Control

Active-Context Control Matrix

A granular checkbox panel that maps every ingested document to one of three retrieval states. Controls how many tokens reach the local LLM's strict 2,048-token context window.

Exclude
Excluded from all retrieval
The document's chunks are filtered out before FTS5 and vector retrieval. Useful for superseded filings, duplicate documents, or irrelevant financial periods that would pollute the context budget.
Insights Only
High-level summary retrieval only
Only the document's wiki/sources/<stem>.md summary page is eligible for retrieval — not individual raw chunks. Preserves context budget while retaining the gist of large background documents.
Full Context
Complete chunk-level retrieval
All chunks from the document are candidates in FTS5 and ONNX vector retrieval. Use for the most critical case documents — the Resolution Plan, Form H, and key NCLT orders that require granular citation.

Persistence & Token Budget

Selections are persisted in concepts/active_rag_docs.json and survive session restarts. The Concepts sidebar shows a live dynamic token count calculation so the practitioner can see exactly how many tokens the current selection will consume from the 2,048-token local LLM budget before sending any query.

FTS5 + Vector Retrieval & Case Entity Graph

Hybrid retrieval pipeline combining sub-millisecond FTS5 keyword search with ONNX cosine similarity reranking — with a live D3.js 3D entity graph for visual case exploration.

Hybrid RAGRRF Fusion

FTS5 + ONNX Hybrid Search

FTS5 full-text index runs first to select candidate chunks via keyword match. ONNX cosine similarity is then computed on-the-fly over their float vector blobs to rerank. Results are merged via Reciprocal Rank Fusion (RRF) for optimal precision. No native C++ binary dependencies — 100% cross-platform.

<1ms FTS5 pass Cosine rerank
Drift-FreeNatural Keys

Drift-Safe Chunk Matching

FTS5 candidates are matched to document_vectors using composite natural keys (filename, section_title, chunk_index) — never raw SQLite rowids. This prevents retrieval failures when the database is rebuilt, compacted, or migrated between machines.

Natural key join Zero drift failures
